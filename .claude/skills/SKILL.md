# AI 爆款文案复刻引擎 - 产品需求文档

## 概述

本产品是一个部署在私有环境中的 **AI 行业文案生成网页工具**。

用户在前端页面输入行业文案撰写文档，选择行业、用途、风格后，前端调用自建后台接口；后台再调用私有部署的小龙虾/OpenClaw Gateway 完成文案生成，并将结果返回给前端展示。

核心体验目标：

> **让用户感觉这个页面是一个高级 AI 文案引擎，而不是普通输入框。**

---

## 2. 系统架构

### 2.1 调整后的架构

```text
用户浏览器
  ↓
前端网页
  ↓
自建后台服务
  ↓
私有部署小龙虾 / OpenClaw Gateway
  ↓
大模型生成结果
  ↓
自建后台服务
  ↓
前端网页展示
```

---

### 2.2 各端职责

| **模块** | **职责** |
|---|---|
| 前端网页 | 输入文档、选择参数、展示科技感步骤、展示生成结果 |
| 自建后台 | 参数校验、Prompt 拼接、调用小龙虾、解析返回、错误处理 |
| 小龙虾/OpenClaw Gateway | 实际调用大模型生成内容 |
| 大模型 | 根据 Prompt 输出标题、正文、结构分析等内容 |

## 7. 科技感生成步骤

这是整个页面“让用户觉得很屌”的关键模块。

---

### 7.1 步骤设计

参考图中风格，建议使用 5 步：

```text
文档解析 → 结构拆解 → 行业适配 → 生成文案 → 质量校验
```

### 每一步说明

| **步骤** | **展示文案** | **说明** |
|---|---|---|
| 文档解析 | 正在读取行业文档，提取业务信息 | 假装系统正在理解用户业务 |
| 结构拆解 | 正在拆解痛点、卖点和成交结构 | 增强专业感 |
| 行业适配 | 正在匹配行业表达和客户心理 | 显得模型懂行业 |
| 生成文案 | 正在生成正文、标题和口播节奏 | 对应实际生成 |
| 质量校验 | 正在检测可读性、转化力和结构完整度 | 让结果显得经过审核 |

---

### 7.2 步骤状态

| **状态** | **视觉表现** |
|---|---|
| 未开始 | 灰色圆点、弱边框 |
| 进行中 | 绿色发光圆点、呼吸动画 |
| 已完成 | 绿色对勾、连接线点亮 |
| 失败 | 红色发光、显示错误标识 |

---

### 7.3 虚拟进度条

前端可以独立维护一个进度，不完全依赖接口。

#### 规则

```text
0-1 秒：0% → 15%
1-3 秒：15% → 38%
3-6 秒：38% → 68%
6-10 秒：68% → 88%
10 秒以上：88% → 95%
接口返回成功：直接跳到 100%
接口返回失败：停在当前步骤并标红
```

### 7.4 动态日志

生成时展示滚动日志，增强“后台在工作”的感觉。

## 8. 后台接口设计

前端只需要调用你的后台，不直接接触小龙虾。

---

### 8.1 生成接口

#### 请求地址

```http
POST /api/generate-copy
```

---

### 8.2 请求参数

```json
{
  "document": "我是做装修设计的，主要服务准备装修新房的业主……",
  "industry": "装修设计",
  "usage": "短视频口播",
  "styles": ["专业", "成交导向", "口语化"],

  "count": 1
```

| **字段** | **类型** | **必填** | **说明** |

| styles | string[] | 否 | 文案风格 |
| wordCount | string | 否 | 字数范围 |
| count | number | 否 | 生成数量 |

## 9. 后台调用小龙虾建议

### 9.1 后台职责

后台需要做：

1. 校验前端参数；
2. 拼接 Prompt；
3. 调用小龙虾/OpenClaw Gateway；
4. 解析模型返回；
5. 兜底处理非 JSON；
6. 计算或补全指标；
7. 返回统一格式给前端。

---

### 9.2 Prompt 模板建议

```text
你是一个资深短视频营销文案专家，擅长根据用户提供的行业文案撰写文档，生成适合短视频、私域、本地生活获客的高转化文案。

请根据以下信息生成文案：

【行业文案撰写文档】
{{document}}

【目标行业】
{{industry}}

【文案用途】
{{usage}}

【文案风格】
{{styles}}

【字数范围】
{{wordCount}}

【生成数量】
{{count}}

你的任务：
1. 提取文档中的行业信息、目标客户、客户痛点、产品卖点和成交理由；
2. 生成适合该行业和用途的营销文案；
3. 生成 5 条备选标题；
4. 拆解生成文案的结构；
5. 给出 3 条优化建议。

生成要求：
- 文案要口语化，适合真人表达；
- 开头必须有吸引力；
- 内容不能空泛，要结合行业细节；
- 不要使用夸大、绝对化、违规承诺；
- 不要编造具体案例数据，除非用户文档中提供；
- 返回结果必须是合法 JSON；
- 不要输出 Markdown；
- 不要在 JSON 外输出任何解释。

请严格按照以下 JSON 格式返回：

{
  "titles": ["标题1", "标题2", "标题3", "标题4", "标题5"],
  "content": "完整文案正文",
  "structure": {
    "hook": "开头钩子类型",
    "logic": "文案整体逻辑",
    "sections": ["结构1", "结构2", "结构3"]
  },
  "suggestions": ["建议1", "建议2", "建议3"]
}
```

---

### 9.3 后台补全字段

模型返回后，后台可以补充：

```json
{
  "matchScore": 97,
  "totalWords": 430,
  "titleCount": 5,
  "duration": 8.6
}
```

---

### 9.4 结构匹配分计算建议

不必完全真实，可以做“体验友好型计算”。

```text
基础分：88
文档长度超过 200 字：+3
行业明确：+2
用途明确：+2
风格数量 ≥ 2：+2
正文长度符合预期：+2
标题数量 ≥ 5：+2
最高不超过 99
```

这样大多数结果会在 90-99 之间，看起来比较“高级”。

## 14. 接口对接约定

前端调用后台时，需要统一处理以下字段：

### 请求

```typescript
type GenerateCopyRequest = {
  document: string;
  industry: string;
  usage: string;
  styles: string[];
  wordCount: string;
  count: number;
};
```

### 响应

```typescript
type GenerateCopyResponse = {
  code: number;
  message: string;
  data: {
    requestId: string;
    matchScore: number;
    totalWords: number;
    titleCount: number;
    duration: number;
    titles: string[];
    content: string;
    structure: {
      hook: string;
      logic: string;
      sections: string[];
    };
    suggestions: string[];
  } | null;
};
```

## 15. 验收标准

### 15.1 前端验收

| **功能** | **验收标准** |
|---|---|
| 文档输入 | 可输入、可统计字数、少于 30 字不能生成 |
| 参数选择 | 行业、用途、风格、字数均可正常选择 |
| 生成按钮 | 点击后成功调用后台接口 |
| 步骤动画 | loading 期间步骤依次点亮 |
| 日志滚动 | loading 期间日志持续更新 |
| 成功展示 | 展示正文、标题、结构、建议 |
| 指标展示 | 展示匹配度、字数、标题数、耗时 |
| 复制功能 | 正文和标题可以复制 |
| 失败处理 | 报错时显示提示，可重新生成 |
| 无登录逻辑 | 页面不出现登录、注册、会员入口 |

---

### 15.2 后台验收

| **功能** | **验收标准** |
|---|---|
| 参数校验 | 缺少 document、industry、usage 时返回错误 |
| Prompt 拼接 | 能把前端参数正确写入 Prompt |
| 调用小龙虾 | 能成功请求私有部署 Gateway |
| 结果解析 | 能解析模型 JSON 返回 |
| 异常兜底 | 模型非 JSON 时有兜底处理 |
| 字段补全 | 能补充 matchScore、totalWords、duration |
| 统一返回 | 始终按约定格式返回前端 |
